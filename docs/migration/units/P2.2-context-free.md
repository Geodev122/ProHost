# Unit P2.2: Context-free view models (learn + plan; executed in sub-steps, each through the Parity Gate)

Goal (MASTER_PLAN P2.2-P2.5): the view models and shared helpers stop taking Android `Context`, so they can move to `commonMain`. **No visible or behavioural change.**

## Learn (8 Nov 2026, source at `app/src/main/java/com/example`)
| Fact | Count / location |
|---|---|
| `ProHostViewModel` functions taking `Context` | 20 (lines ~281-1326): `refreshEmailVerification`, `resendEmailVerification`, `updateProfilePhoto(context, uri)`, `updateAddress`, `launchWhatsAppToPractitioner`, `acceptBookingRequest(context, id, agreementUri)`, `sendPaymentReminder`, `rejectBookingRequest`, `cancelBookingRequest`, `acknowledgePayment`, `toggleSavedSpace(context?)`, `setListingStatus`, `addBlackoutSlot`, `removeBlackoutSlot`, `addSubdivision`, `removeSubdivision`, `shareExportData`, `shareListing`, `copyListingLink`, private `reportFailure(appContext, e, @StringRes)` (12 call sites) |
| `UiMessages.show(context, ...)` | 85 call sites in 20 files; the object already owns a `SharedFlow`; `Context` is used **only** for the Toast fallback (`context.applicationContext`) when no Snackbar host is on screen |
| `uiText(...)` / `uiPlural(...)` | 384 call sites; resolves through the application `Resources` (`UiText.init` in `ProHostApplication`), follows the per-app language |
| `getString(` inside `ui/viewmodel/` | 38 (mostly `appContext.getString(R.string.x)` that `uiText(R.string.x)` replaces with the same text) |
| `LocalContext.current` in composables | 40 (UI layer; handled in P2.5 seams, not here) |
| Real Android work behind the `Context` params | (a) string lookup, (b) the Toast fallback, (c) **Activity-bound intents**: WhatsApp, share chooser, calendar, copy-to-clipboard (`launchWhatsAppToPractitioner`, `shareExportData`, `shareListing`, `copyListingLink`), (d) `ContentResolver` reads for picked files (`updateProfilePhoto`, `acceptBookingRequest` agreement) |

## Plan (smallest identical-behaviour steps, each its own commit + Parity Gate run)
1. **P2.2a `UiMessages` without `Context`.** Add `show(text, long, actionLabel, onAction)` and `UiMessages.init(applicationContext)` (called from `ProHostApplication.onCreate`) for the Toast fallback; keep `show(context, ...)` as a delegating overload so nothing else changes. Toast is shown on the same application context as before. Proof: gate (pixels + unit tests), plus a new unit test for the fallback path using a fake toast hook.
2. **P2.2b Migrate the 85 call sites** file by file from `show(context, x)` to `show(x)`; then delete the old overload. Mechanical; gate per batch of files.
3. **P2.2c Strings:** replace `appContext.getString(R.string.x, args)` in view models with `uiText(R.string.x, args)`; verify equality of the English and Arabic text with the string-key parity script and the existing tests that read messages.
4. **P2.2d `reportFailure` and the simple actions** (`setListingStatus`, `addBlackoutSlot`, `addSubdivision`, ... ) lose their `context` parameter (callers in screens updated); behaviour unchanged because after 2-3 the parameter is unused.
5. **P2.2e Platform actions behind a seam:** `PlatformActions` (WhatsApp, share, copy, open link, calendar) with the Android implementation holding a weak reference to the current Activity (the same pattern `BillingController` already uses), set by `MainActivity`; the four intent functions call it. Needed because these intents are started from an **Activity** today (chooser, task and transition behaviour must not change; an application context would need `FLAG_ACTIVITY_NEW_TASK`). Picked-file functions take a `PickedFile`/reader instead of `Uri` + `ContentResolver` (P2.4).
6. Update `PARITY.md` rows (`UiMessages.kt`, `ProHostViewModel.kt`) and `PROGRESS.md` after each green gate.

## Compare (every step)
Parity Gate: compile debug + release, all unit tests, R8 release shrink, 280-render diff vs `golden-v1047` = 0 differences. Behaviour checks for steps 4-5 that pixels cannot prove: the toast/snackbar fallback test (2a), message text equality EN/AR (3), and an instrumented-style Robolectric test that each of the four intent functions fires the same `Intent` action/extras/chooser as before (5), written **before** the change against the current code and kept unchanged after it.

## Risks
- Share/WhatsApp must keep launching from the Activity. Mitigation: step 5 test first; keep the weak Activity reference.
- `UiText.resources` must be initialised before the first message in tests that never create the Application (existing tests already handle this; add the same init to new tests).
- Do not change analytics: `reportFailure` keeps logging `app_error` with the English area key.
