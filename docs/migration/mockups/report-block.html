Report and block

Apple requires every app with user-created content to let people report content, block other users, and to act on reports within 24 hours. This is the one planned addition to the app. It would be added to Android and iOS together, with a review queue in the web admin console. Example names and listings below are invented.

Step 1

Where people find it

A three-dot menu on the listing page (for specialists) and on a booking request (for hosts). Nothing else on those pages moves.

Step 2

Sending a report

One sheet: pick a reason, add details if you want, send. The reported person is never told who reported them.

Step 3

Blocking and unblocking

Blocking is private and immediate. The list of blocked people lives in Profile › More, next to Language and Legal.

Step 4

Review queue in the web admin console

A new "Reports" list in the Security tab. Admins see who reported; hosts and specialists never do. Each action is written to the audit log.

Your decisions

What I need you to confirm

  1. The six reasons. Keep this list, or change any wording?
  2. What a block does. Proposed: the blocker stops seeing the other person's listings, and the blocked person's booking requests to them are refused. Existing bookings are untouched. The blocked person is not told.
  3. Where it sits. A three-dot menu on the listing page and on request details, plus "Blocked people" in Profile › More. The listing page's top bar gains the three-dot button; nothing else moves.
  4. The 24-hour promise. The confirmation says reports are reviewed within 24 hours, which is what Apple asks for. Someone must check the queue daily.
  5. Admin actions. Dismiss, hide the listing, suspend the user. "Hide" and "Suspend" reuse the existing listing toggle and owner suspension.
