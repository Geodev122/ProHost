# iOS plan for ProHost (written 5 Nov 2026)

**Status:** no iOS code exists. ProHost is a native Android app (Kotlin, Jetpack Compose; about 49k lines, 18 screens, 1,225 strings in English and Arabic).
The owner has created an Apple Developer account. This file is the shared plan; update it as decisions are made.

## What the backend already gives iOS
Firestore, callable functions, FCM push (works on iOS through APNs), Auth, the entitlement manager (`subscriptionPlatform` field exists; Android writes `"android"`), display codes, booking logic mirrored in `functions/src/**`.
Android-only today: Google Play Billing, Play Integrity at sign-in (`assignInitialRole`), `assetlinks.json`, Credential Manager, Google Maps for Compose.

## Decision needed from the owner
1. **Approach.** Recommended: a **native SwiftUI client** on the existing backend (lowest risk to the live Android app, best App Store review experience, first-class Firebase/StoreKit/Sign in with Apple).
   Alternatives: Kotlin/Compose Multiplatform (big refactor of the live app), Flutter/React Native (full rewrite). A PWA is not a substitute for the App Store listing.
2. Account type (Individual or Organization; the seller name shown on the App Store comes from it) and the **Team ID**. 3. Bundle ID (recommended `app.geonajjar.prohost`, same as Android). 4. Mac available, or build in CI (GitHub macOS runners / Xcode Cloud).

## Owner steps (Apple and Firebase side)
1. developer.apple.com: enrollment active, two-factor on the Account Holder Apple ID. 2. App Store Connect > Business: accept the **Paid Apps Agreement**, add bank and tax forms (needed to sell subscriptions); declare **trader status** (EU).
3. Certificates, Identifiers & Profiles > Identifiers: create the App ID with capabilities **Sign in with Apple, Push Notifications, Associated Domains, In-App Purchase** (and App Attest for App Check).
4. Keys (Certificates, Identifiers & Profiles > Keys, and Users and Access > Integrations): **APNs Auth Key** (.p8), **App Store Connect API key** (Issuer ID, Key ID, .p8, for CI), **In-App Purchase key** (for server validation). Keep .p8 files out of chat and the repo: GitHub secrets or Secret Manager only.
5. Firebase console > project prohost-f766f: add the iOS app (bundle ID) and download `GoogleService-Info.plist`; Authentication > enable **Apple**; Cloud Messaging > upload the APNs key; App Check > register **App Attest**.
6. App Store Connect > Apps > New app (name, SKU, bundle ID, category, age rating). Subscription group **ProHost Premium** with Monthly ($8.99) and Yearly ($79.99) plus the same introductory offers as Play (monthly first month free, yearly 50% off the first year).
7. Store assets: 6.9-inch iPhone screenshots, privacy policy URL and support URL (interim working URLs: `https://europe-west1-prohost-f766f.cloudfunctions.net/legalDocumentPage/privacy` and `/delete-account`), App Privacy answers, a **demo account** for App Review.
8. Send Claude: Team ID, chosen bundle ID, approach decision.

## Apple review rules that affect ProHost
Digital subscriptions must use **In-App Purchase** (3.1.1). Because Google sign-in is offered, **Sign in with Apple** must be offered (4.8); the Android code already has an Apple slot (`AuthProviders.APPLE_ENABLED`). In-app **account deletion** is required (exists: `deleteOwnAccount`).
Listings are user-generated content: Apple expects a report/block mechanism (1.2); check the app has one before submitting. Subscription terms, price and renewal text must be shown in the paywall (`SubscriptionTermsFooter` equivalent).
